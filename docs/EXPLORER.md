# Hold'em explorer

Local HTTP study server for one flop, turn, or river. Separate binary from the CLI solvers; same `StreetBatchSolver` engine.

From the repository root:

```sh
explorer
```

Open `http://127.0.0.1:8765`. The server listens on `127.0.0.1` only. `--port` changes the port. Every response includes CORS headers (`Access-Control-Allow-Origin: *`, methods, `Content-Type`, and `Access-Control-Allow-Private-Network`) and `OPTIONS` returns 204 so the packaged Study webview can call the API cross-origin. `--max-pair-runouts N` and `POKER_EQUITY_MAX_PAIR_RUNOUTS` set the check-down equity work limit for node and river equity queries; the flag wins over the environment variable, and both default to `kDefaultMaxPairRunouts` (1,100,000). A request above that limit fails before showdown evaluation with the required and allowed pair-runout counts. The default admits a full-range river and still rejects a full-range turn. Static files come from `ui/` in the working directory, or from `ui/` next to the executable and one or two directories above it. On Linux that directory is the parent of `/proc/self/exe`.

Saved street-config templates live under `configs/templates`. `GET /api/templates` returns a JSON array of `{"id","name"}` entries (`id` is the filename stem). `GET /api/templates/{id}` returns `{"id","text"}` with the raw `street-config 1` document. Unknown ids and path tricks such as `..` are HTTP 404. The directory is `POKER_SOLVER_TEMPLATES` when that environment variable is set to an existing directory; otherwise the server looks for `configs/templates` in the working directory, then next to the executable and one or two parents up (the same layout search as `ui/`).

Named range presets live under `configs/ranges`. `GET /api/ranges` returns a JSON array of `{"id","name"}` entries (`id` is the filename stem). `GET /api/ranges/{id}` returns `{"id","text"}` with the raw range string the solver already parses. Unknown ids and path tricks such as `..` are HTTP 404. The directory is `POKER_SOLVER_RANGES` when that environment variable is set to an existing directory; otherwise the server looks for `configs/ranges` in the working directory, then next to the executable and one or two parents up (the same layout search as `ui/`). The library is flat: only regular files in that directory are listed. The page offers a preset dropdown that applies the text into the OOP or IP range field and grid.

The board length chooses where the hand starts. Three cards solve the flop, the turn, and the river in one tree: the turn and the river are dealt inside that tree, and each street is bet. Four cards solve the turn and the river the same way. Five cards are the river only, because the flop and the turn have already been dealt. Flop, turn, and five-card river solves all use `StreetBatchSolver`. Older river-kind PSOL checkpoints still reopen on `RiverBatchSolver`. Painting a range writes the same text the solver already parses: `AA`, `AKs`, `AKo:0.5`, `QQ+`, `22-77`, `ATs+`. A weight slider sets the next paint. Clicking a cell that already has that weight clears it. Dragging paints the chosen weight across cells. Cards on the board are grey and cannot be selected. Undo and redo restore prior OOP and IP combo-weight grids after a paint stroke, text apply, clear, or config load, with Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z or Y.

`POST /api/plan-memory` accepts the same job JSON as solve (or `{"text":"street-config 1
…"}`) and returns the mid-construction dry-run plan: `estimated_peak_bytes`, budget, deal/infoset counts, `fits_budget`, and `dry_run: true`. It does not train and does not keep an engine. `estimated_peak_bytes` is a labeled plan, not measured allocation and not process RSS. `POST /api/tree-preview` builds the same plan-only public tree and returns nodes with display + compact action labels plus the applied `tree_edits` array. Solve jobs may include `tree_edits` as a string blob or an array of `TreeEditSet` lines (`force - c`, `remove c/b50 b50`, `add-size - 0.33`); those edits reshape the betting tree before training. `POST /api/config` on a street document echoes `tree_edits` the same way. The Study Build workspace’s line editor drives both endpoints.

Empty per-street size boxes use the shared bet list. A geometric size, an all-in threshold, an accuracy stop, a wall-clock time limit, eval samples, pot rake, tournament ICM, opponent incentives, an OOP donk size, a pot cap, and a switch that removes the 3-bet are optional. Donk sizes are used when the previous street was bet by the in-position player. A pot cap of 1 cuts a larger size down to the pot. The 3-bet switch removes the re-raise after a bet and a raise. Fixed chip amounts and raise multiples such as `20c` and `3x` are set on the `street_solver` command line. Accuracy is a fraction of the pot and stops the run when the Nash gap is at most that fraction of the pot. `time_limit` is seconds of wall clock for that solve or continue; when set to a non-negative value, training stops after a completed sample chunk once elapsed time meets the limit, publishes the solve, and sets `time_limit_reached`. Omit the field (or leave the page field blank) to leave the limit off. `samples` (default 5, clamped 1–20) is the number of progress/eval chunks across the requested iterations; the page exposes it as Eval samples. `rake_rate` is a fraction of the terminal pot in `[0, 1]` and `rake_cap` is a non-negative chip ceiling (`0` means uncapped); both default to `0` (no rake) and are echoed on status. Invalid rake values are HTTP 400. See [RAKE.md](RAKE.md). `icm_stacks` and `icm_payouts` are optional number arrays (empty / omitted = chip EV); when stacks are non-empty they must pass `IcmConfig::validate` for the job pot and effective stack, and status echoes both arrays. Invalid ICM values are HTTP 400. See [ICM.md](ICM.md). `incentives` is an optional array of `{kind,player,key,delta}` objects (`kind` is `label` or `tag`); `edge_tags` is an optional array of `{player,action,tags}` objects that assign mid-tree CategoryTag labels on matching public edges. Both default to empty (incentives off) and are echoed on status. Invalid incentive values are HTTP 400. See [INCENTIVES.md](INCENTIVES.md). Do not treat status `nash_gap` as a chip Nash claim when incentives are active. The algorithm selector offers CFR+ (default), vanilla CFR, and DCFR (1.5, 0, 2). DCFR requires the frozen combo pass; the page checks frozen when DCFR is selected, and the server rejects DCFR without frozen. Five-card boards use `StreetBatchSolver` (same as flop/turn); older river-kind PSOL files still open on `RiverBatchSolver` but cannot carry DCFR. The frozen combo pass is offered on a flop, a turn, or a river. Threads above 1 still require frozen.

A finished flop, turn, or river stays on the server as one street solution. Status polls report the job, the value, the Nash gap, and the engine heap. Strategy rows come from a node request. The page then asks for the root node, and each button asks for that child only. A new solve expires the previous solution id. Saves use the street-config PSOL path. Older river-kind checkpoints still open. The ordinary export button writes the node currently on screen. A generic `/export` remains strategy-only.

A completed solve keeps one record: the configuration, the iterations that finished, the runtime, the out-of-position value, both best-response values, the Nash gap, the sample series, and the street memory report when the tree has one. Status and export are written from that record. A metric that was not computed is JSON null. A river export has no engine-heap report, so those fields are null. A node response names the solution id and the job id and stays limited to that node. A chance node lists every undealt card. Its weight is the current average-profile probability of that card, from the two players' marginals, in time linear in the hand counts. At zero joint reach the weights are null. Node responses include `X-Query-Seconds` and `X-Serialize-Seconds` for that page.

An absent `oop_bets` or `ip_bets` key still defaults to `0.5, 1`. A present empty array stays empty, so a check-only tree can be requested. All-in remains its own switch.

Successful Save and Open calls append the solution path to a bounded most-recently-used list (newest first, capped at 10, deduplicated by normalized path). The list is a JSON array of `{"path","name","mtime"}` objects in `~/.poker-solver/recent_psol.txt` by default. Set `POKER_SOLVER_RECENT_FILE` to override that sidecar path. `GET /api/recent-solutions` returns the list and drops entries whose files are missing. `POST /api/recent-solutions/clear` empties it. Reopening a recent path uses the same `POST /api/open` validation as Open; the recent list does not bypass that path. The page Recent dropdown loads that list and opens the chosen path through Open. This is not a compact or multi-file solution library.

`GET /api/solutions/{id}/nodes/{node_id}/values` is a separate request. Status polls and ordinary node pages do not compute it. The node must be a decision on a street solve, including a five-card river. A chance or terminal node returns 400. An expired solution returns 404. The body names the solution, the job, the node, and the status generation. `units` is `chips` and `utility_basis` is `root_centered`: the same net chips as the recorded solver EV, including earlier investments. `local_offset` is `-U_i(fold-now)` for the acting seat so a client can form local decision EV by adding it (chips already invested are sunk; Fold displays as 0 under ordinary chip/ICM terminals). Study UIs default to that local basis and keep a Global toggle for root-centered chips. Combo and action order match the node page. `ev_defined` is per hand. Undefined action values and mixed values are null. `node_ev` is the posterior-weighted mixed value, or null when that average is undefined. A zero-reach hand can still be defined when some compatible opponent reach remains.

`GET /api/solutions/{id}/nodes/{node_id}/categories` reports category composition from strategy-weighted reaches. `GET /api/solutions/{id}/categories` is the river-root form and uses the configured ranges. On a five-card board, `model` is `made-hand` and `exclusive` is true: categories are `poker::holdem::HandCategory` labels from high card through straight flush, and each player's `fractions` sum to 1 over positive reach mass when `defined` is true. On a flop or turn board, `model` is `draws` and `exclusive` is false: categories are flush draw, oesd, gutshot, backdoor flush, and backdoor straight. Each fraction is the share of positive reach mass that carries that tag (multi-label; the fractions need not sum to 1). Backdoor tags apply on the flop only. Boards that are not length 3, 4, or 5 set `available` to false with a reason.

`GET /api/solutions/{id}/nodes/{node_id}/equity` (and the river root `/equity`) returns check-down showdown equity, not chip EV. `model` is `check-down` and `units` is `fraction of the pot`. When defined, `oop_equity` and `ip_equity` are range averages. The body also carries a fixed ten-bucket histogram: `equity_distribution` for OOP and `ip_equity_distribution` for IP. Each entry is `{lo, hi, weight}` over `[0, 0.1)`, …, `[0.9, 1.0]` (last bucket includes 1). Weights are raw combo input masses; they sum to the counted mass. Compact combo rows `oop_hands` / `ip_hands` list `{combo, equity, weight}` for defined positive-weight combos so the Study client can filter histogram bands and inspect shape composition. The desktop Equity tab draws the histograms, band filters, and composition; this remains check-down equity, not chip EV.

`GET /api/ranges` lists named presets under `configs/ranges` (or `POKER_SOLVER_RANGES`), including nested folders. Each entry is `{id, name, folder}` where `id` uses `/` separators (for example `open/utg-open`) and `folder` is the relative directory (empty at the root). `GET /api/ranges/{id}` returns `{id, folder, text}`; path traversal and unsafe segments are rejected.

The accept loop does not walk the tree. A new node returns 202 with `pending: true` until the one background query finishes, then 200. A repeat for that same node and profile returns the stored page, and `query_seconds` stays the walk time. `X-Query-Seconds` is only the time spent in the handler. A newer node, or `POST /api/solve`, cancels the walk before the next solve begins. Cancellation is checked at public-node boundaries, not inside one terminal batch. The worker borrows the solution through a reader lease: the engine reference is dropped before the reader count reaches zero, so a replacement can destroy the old engine before it constructs the next one. A result is kept only when the solution id is unchanged. The worker's shutdown is idempotent. It joins on server teardown, before the session is destroyed, and it joins before the solve thread so a quiet wait is not left holding that reader.

The solver cache key is the canonical node id plus the profile epoch. `p00.t-1.r-1` is the root. The epoch advances when training, a reset, a continuation, or an explicit average edit changes the profile. A reader that rebuilds the average does not advance it. Those mutations need exclusive ownership of the solver. A real cache hit reports solver `query_seconds` of 0. The HTTP body keeps the original walk time. The solver keeps one numerical page and the epoch, both outside the engine budget. The HTTP layer keeps one serialized body. A query also makes temporary copies and reach vectors. Retaining one node does not mean one physical copy, and it does not put that memory inside the engine budget. The generic `/export` stays strategy-only. The on-screen export includes values only when they belong to that exact node and solution.

The page shows **Calculate EVs** on a decision. It does not fetch values while painting the grid or polling status. The note states the chip basis. A selected group shows the posterior-weighted mixed EV and the value of forcing each action. A group with no reaching mass stays undefined. Pending, failed, and undefined states stay visible. A reply is discarded when its selection, solution, or status generation is stale.

Solution ids are `sN` and job ids are `jN`. Parsing uses the whole token. An overflowing, truncated, signed, or otherwise malformed id is HTTP 400. A well-formed id for any other solution is HTTP 404. Leading zeros that denote the same number select that number; `s00` is solution 0. Published solution ids start at 1. Node components use the same complete parse. A node index below 0 or past the tree is an unknown node.

Stop and publication share one state machine. `POST /api/stop` accepts an optional `{"job_id":"jN"}`. Omitting it stops the current job. The result is `accepted`, `complete`, or `stale`. A stop accepted before publication finishes the in-flight numerical work, marks the job cancelled, and publishes no solution. A stop after at least one completed iteration publishes that solve as completed with `cancelled` true. A stop after publication leaves the completed result in place. A stop for an old job does not cancel the job that replaced it. A constructor failure, a thread-launch failure, or a publication failure ends in the failed state. A failed or cancelled job has no queryable solution. Replacing a solution waits until current readers finish, drops the old engine, and only then builds the next one.

`POST /api/pause` uses the same optional `job_id` shape and result vocabulary. Pause is distinct from stop-and-keep: after the current training chunk finishes, the solve publishes a browsable solution with `running` false and `paused` true (`Phase::Paused`). A pause before any completed iteration does not publish; the flag stays set until a chunk finishes. Stop wins if both are requested. Status JSON always exposes `running` and `paused` so the page can tell a live job from a paused one.

`POST /api/solutions/{id}/continue` with `{"iterations":N}` trains N more iterations on that published solution, including a paused one. An optional `time_limit` (non-negative seconds) arms a wall-clock stop for that continuation only; omit it to leave continue unlimited. There is no separate `/api/resume`. The solution id stays. Regrets, average weights, and the iteration count continue from the stored state. The same algorithm and frozen setting are used. Held node locks (if any) are applied for those iterations. The request cancels an in-flight value query and waits until no reader holds the engine, then browsing is suspended until the continuation is published. A stop during the continuation keeps the chunks that finished and leaves that same solution completed. A pause during the continuation leaves it paused again. A time-limit stop keeps the finished chunks, leaves the solution completed, and sets `time_limit_reached`. An exception leaves the engine queryable. Status, export, history, and the next continuation use the iterations the engine actually completed, including the job id for that training. A missing solution is 404. An iteration count that is missing, non-finite, or not an integer from 1 through 1000000000 is 400, and that rejection does not stop the process. A negative or non-finite `time_limit` is 400. A continuation while a solve is running is 409. The page drops the node on screen when the continuation is accepted and loads it again when the run finishes, including when the solution id is unchanged.

Node locks (street solutions; public-node id `pN.t-1.r-1` maps to infoset `N`):

- `GET /api/solutions/{id}/locks` lists held locks
- `PUT /api/solutions/{id}/locks` with `{"node_id","kind":"full"|"selected","hand_indices","probs"}` upserts a lock after validating action arity via `inspect_node`
- `DELETE /api/solutions/{id}/locks?node_id=...` (or `/locks/{node}`) removes one lock; omit the node to clear all
- `POST /api/solutions/{id}/resolve-locked` with `{"iterations":N}` and optional `accuracy` / `samples` / `time_limit` / `warm_start` retains the current revision as a Session baseline. Default rebuilds and re-solves from zero with locks. `warm_start:1` keeps regrets/strategy-sums and continues N more iterations under locks. Publishes a new solution id; status exposes `baseline_solution_id`. Baseline export/nodes stay queryable
- `DELETE /api/solutions/{id}/locks?node_id=…&hand_index=K` removes one combo from a SelectedCombos lock (erases the node lock when none remain). Full-node locks unlock with `node_id` only
- `GET /api/compare?baseline=sA&scenario=sB&node_id=...` returns root EV/gap for both revisions plus per-hand strategy vectors, deltas, and locked-hand marks

Free-form strategy edits (distinct from locks — rewrite the prepared average profile for browse/EV; do not constrain CFR):

- `GET /api/solutions/{id}/strategy-edits` lists session overlays (`edits` plus `persisted:false`)
- `PUT /api/solutions/{id}/strategy-edits` with `{"node_id","kind":"full"|"selected","hand_indices","probs"}` validates nonnegative probs that sum to 1 (same tolerance as locks), applies them via `set_average_strategy`, and bumps `profile_epoch` so cached value pages drop
- `DELETE /api/solutions/{id}/strategy-edits?node_id=...` (or omit the node) clears one node or all overlays and rebuilds the average from strategy sums; `hand_index` clears one SelectedCombos hand
- Continue / resolve-locked discard session strategy edits (training rebuilds the average). Locks are unchanged by these routes
- **PSOL limitation:** strategy edits are session-scoped only. PSOL v2 still persists `locks_text` only; free-form strategy overlays are not saved or restored

Save/Open uses PSOL payload version 2 with a trailing `locks_text` field (`format_lock_set`). Version 1 files still open with empty locks. Algorithm tags are `0` vanilla, `1` CFR+, `2` linear, `3` DCFR(1.5,0,2); unknown tags fail without mutating the previous file. A reopened solution continues with its stored algorithm.

## Themes

The page defaults to the **light** theme (`theme-light` on `body`). A header button switches to **dark** (`theme-dark`). Colors and surfaces are CSS variables in `ui/app.css`. The choice is stored under the `explorer-theme` key in `localStorage` and restored on reload. Saved layouts and localization are still ahead.

The page then shows:

- The street, pot, stack, board, out-of-position value, the Nash gap, and the gap as a fraction of the pot
- A Nash-gap chart across the samples taken during the run
- A 13×13 strategy matrix for the player to act, separate from the range grids. The frequency menu defaults to the total of every bet and raise. It also lists each action at the node. A cell's color is the selected frequency. The denominator is the group's marginal reach. Positive reach with no aggression shows 0. A group with no reach shows the frequency as undefined. A cell lists the suit combos and every action's probability
- Buttons for the legal actions, or for the next public card. Each button loads that node
- **Continue** adds the iteration-box count to a completed or paused published solution and reloads that solution when the added iterations finish. **Pause** during a run keeps the finished chunks as paused so Continue can resume them. **Stop** during a continuation keeps the finished chunks as completed. **Stop** during a new solve still publishes nothing until at least one iteration has finished
- **Calculate EVs** on a flop, turn, or river decision (including five-card boards on the shared street tree). The page defaults to local decision EV (Fold = 0; chips already invested are sunk) and can switch to root-centered global chips. Per-combo rows show each action's conditional EV and the mixed EV. A group line weights those by the current marginals
- **Hand categories** on flop/turn/river: made-hand fractions on five-card boards; multi-label draw/backdoor tags on flop and turn
- Export writes the node on screen. A node export carries values only after they were calculated for that same node

## Keyboard shortcuts

When focus is not in an `input`, `textarea`, or `select`, these keys run the matching page control if that control is enabled:

| Key | Action |
| --- | --- |
| `s` | Solve |
| `x` | Stop |
| `c` | Continue |
| `b` | Focus the board field |
| `?` | Toggle the on-page shortcuts help |

Modifier chords (`Ctrl`, `Alt`, `Meta`) are ignored. There is no Undo control on this page, so no undo shortcut.

The default spot is aces versus kings on `Ah Kd 7c 4s 2h` (same tree as `configs/river_default.json`, 200 iterations instead of 500). Every board length uses `StreetBatchSolver` and sends `memory_mib` (default 1024) and `threads` (default 1). Threads above 1 require the frozen pass; a non-frozen multi-thread request is rejected before the solve starts. If the tree does not fit, the page keeps running and shows the budget error. The 200,000-terminal limit belongs to the `StreetGame` reference enumerator.
