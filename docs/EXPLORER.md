# Hold'em explorer

`explorer` is a local page for one flop, turn, or river. It is a separate program from the solvers.

From the repository root:

```sh
explorer
```

Open `http://127.0.0.1:8765`. The server listens on `127.0.0.1` only. `--port` changes the port. `--max-pair-runouts N` and `POKER_EQUITY_MAX_PAIR_RUNOUTS` set the check-down equity work limit for node and river equity queries; the flag wins over the environment variable, and both default to `kDefaultMaxPairRunouts` (1,100,000). A request above that limit fails before showdown evaluation with the required and allowed pair-runout counts. The default admits a full-range river and still rejects a full-range turn. Static files come from `ui/` in the working directory, or from `ui/` next to the executable and one or two directories above it. On Linux that directory is the parent of `/proc/self/exe`.

The board length chooses where the hand starts. Three cards solve the flop, the turn, and the river in one tree: the turn and the river are dealt inside that tree, and each street is bet. Four cards solve the turn and the river the same way. Five cards are the river only, because the flop and the turn have already been dealt. Five cards use the river public tree. Three or four cards use the turn and flop public tree. Painting a range writes the same text the solver already parses: `AA`, `AKs`, `AKo:0.5`, `QQ+`, `22-77`, `ATs+`. A weight slider sets the next paint. Clicking a cell that already has that weight clears it. Dragging paints the chosen weight across cells. Cards on the board are grey and cannot be selected. Undo and redo restore prior OOP and IP combo-weight grids after a paint stroke, text apply, clear, or config load, with Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z or Y.

Empty per-street size boxes use the shared bet list. A geometric size, an all-in threshold, an accuracy stop, an OOP donk size, a pot cap, and a switch that removes the 3-bet are optional. Donk sizes are used when the previous street was bet by the in-position player. A pot cap of 1 cuts a larger size down to the pot. The 3-bet switch removes the re-raise after a bet and a raise. Fixed chip amounts and raise multiples such as `20c` and `3x` are set on the `street_solver` command line. Accuracy is a fraction of the pot and stops the run when the Nash gap is at most that fraction of the pot. The frozen combo pass is offered on a flop, a turn, or a river. Threads above 1 still require frozen.

A finished flop, turn, or river stays on the server as one street solution. Status polls report the job, the value, the Nash gap, and the engine heap. Strategy rows come from a node request. The page then asks for the root node, and each button asks for that child only. A new solve expires the previous solution id. Saves use the street-config PSOL path. Older river-kind checkpoints still open. The ordinary export button writes the node currently on screen. A generic `/export` remains strategy-only.

A completed solve keeps one record: the configuration, the iterations that finished, the runtime, the out-of-position value, both best-response values, the Nash gap, the sample series, and the street memory report when the tree has one. Status and export are written from that record. A metric that was not computed is JSON null. A river export has no engine-heap report, so those fields are null. A node response names the solution id and the job id and stays limited to that node. A chance node lists every undealt card. Its weight is the current average-profile probability of that card, from the two players' marginals, in time linear in the hand counts. At zero joint reach the weights are null. Node responses include `X-Query-Seconds` and `X-Serialize-Seconds` for that page.

An absent `oop_bets` or `ip_bets` key still defaults to `0.5, 1`. A present empty array stays empty, so a check-only tree can be requested. All-in remains its own switch.

`GET /api/solutions/{id}/nodes/{node_id}/values` is a separate request. Status polls and ordinary node pages do not compute it. The node must be a decision on a street solve, including a five-card river. A chance or terminal node returns 400. An expired solution returns 404. The body names the solution, the job, the node, and the status generation. `units` is `chips` and `utility_basis` is `root_centered`: the same net chips as the recorded solver EV, including earlier investments. Combo and action order match the node page. `ev_defined` is per hand. Undefined action values and mixed values are null. `node_ev` is the posterior-weighted mixed value, or null when that average is undefined. A zero-reach hand can still be defined when some compatible opponent reach remains.

`GET /api/solutions/{id}/nodes/{node_id}/categories` reports made-hand category composition on the current board from strategy-weighted reaches. `GET /api/solutions/{id}/categories` is the river-root form and uses the configured ranges. `model` is `made-hand`. Categories are `poker::holdem::HandCategory` labels from high card through straight flush. Each player's `fractions` sum to 1 over that player's positive reach mass when `defined` is true. Incomplete boards (flop or turn without the river card) set `available` to false with a reason and omit per-player masses. This is the made hand on the five-card board only; draws and backdoors are not reported.

`GET /api/solutions/{id}/nodes/{node_id}/equity` (and the river root `/equity`) returns check-down showdown equity, not chip EV. `model` is `check-down` and `units` is `fraction of the pot`. When defined, `oop_equity` and `ip_equity` are range averages. The body also carries a fixed ten-bucket histogram: `equity_distribution` for OOP and `ip_equity_distribution` for IP. Each entry is `{lo, hi, weight}` over `[0, 0.1)`, …, `[0.9, 1.0]` (last bucket includes 1). Weights are raw combo input masses; they sum to the counted mass. The page shows the averages; it does not yet draw the histogram.

The accept loop does not walk the tree. A new node returns 202 with `pending: true` until the one background query finishes, then 200. A repeat for that same node and profile returns the stored page, and `query_seconds` stays the walk time. `X-Query-Seconds` is only the time spent in the handler. A newer node, or `POST /api/solve`, cancels the walk before the next solve begins. Cancellation is checked at public-node boundaries, not inside one terminal batch. The worker borrows the solution through a reader lease: the engine reference is dropped before the reader count reaches zero, so a replacement can destroy the old engine before it constructs the next one. A result is kept only when the solution id is unchanged. The worker's shutdown is idempotent. It joins on server teardown, before the session is destroyed, and it joins before the solve thread so a quiet wait is not left holding that reader.

The solver cache key is the canonical node id plus the profile epoch. `p00.t-1.r-1` is the root. The epoch advances when training, a reset, a continuation, or an explicit average edit changes the profile. A reader that rebuilds the average does not advance it. Those mutations need exclusive ownership of the solver. A real cache hit reports solver `query_seconds` of 0. The HTTP body keeps the original walk time. The solver keeps one numerical page and the epoch, both outside the engine budget. The HTTP layer keeps one serialized body. A query also makes temporary copies and reach vectors. Retaining one node does not mean one physical copy, and it does not put that memory inside the engine budget. The generic `/export` stays strategy-only. The on-screen export includes values only when they belong to that exact node and solution.

The page shows **Calculate EVs** on a decision. It does not fetch values while painting the grid or polling status. The note states the chip basis. A selected group shows the posterior-weighted mixed EV and the value of forcing each action. A group with no reaching mass stays undefined. Pending, failed, and undefined states stay visible. A reply is discarded when its selection, solution, or status generation is stale.

Solution ids are `sN` and job ids are `jN`. Parsing uses the whole token. An overflowing, truncated, signed, or otherwise malformed id is HTTP 400. A well-formed id for any other solution is HTTP 404. Leading zeros that denote the same number select that number; `s00` is solution 0. Published solution ids start at 1. Node components use the same complete parse. A node index below 0 or past the tree is an unknown node.

Stop and publication share one state machine. `POST /api/stop` accepts an optional `{"job_id":"jN"}`. Omitting it stops the current job. The result is `accepted`, `complete`, or `stale`. A stop accepted before publication finishes the in-flight numerical work, marks the job cancelled, and publishes no solution. A stop after publication leaves the completed result in place. A stop for an old job does not cancel the job that replaced it. A constructor failure, a thread-launch failure, or a publication failure ends in the failed state. A failed or cancelled job has no queryable solution. Replacing a solution waits until current readers finish, drops the old engine, and only then builds the next one.

`POST /api/solutions/{id}/continue` with `{"iterations":N}` trains N more iterations on that published solution. The solution id stays. Regrets, average weights, and the iteration count continue from the stored state. The same algorithm and frozen setting are used. The request cancels an in-flight value query and waits until no reader holds the engine, then browsing is suspended until the continuation is published. A stop during the continuation keeps the chunks that finished and leaves that same solution in place. An exception leaves the engine queryable. Status, export, history, and the next continuation use the iterations the engine actually completed, including the job id for that training. A missing solution is 404. An iteration count that is missing, non-finite, or not an integer from 1 through 1000000000 is 400, and that rejection does not stop the process. A continuation while a solve is running is 409. The page drops the node on screen when the continuation is accepted and loads it again when the run finishes, including when the solution id is unchanged.

The page then shows:

- The street, pot, stack, board, out-of-position value, the Nash gap, and the gap as a fraction of the pot
- A Nash-gap chart across the samples taken during the run
- A 13×13 strategy matrix for the player to act, separate from the range grids. The frequency menu defaults to the total of every bet and raise. It also lists each action at the node. A cell's color is the selected frequency. The denominator is the group's marginal reach. Positive reach with no aggression shows 0. A group with no reach shows the frequency as undefined. A cell lists the suit combos and every action's probability
- Buttons for the legal actions, or for the next public card. Each button loads that node
- **Continue** adds the iteration-box count to the published solution and reloads that solution when the added iterations finish. **Stop** during that run keeps the finished chunks. **Stop** during a new solve still publishes nothing
- **Calculate EVs** on a flop, turn, or river decision (including five-card boards on the shared street tree). The label is chips, root-centered, including earlier investments. Per-combo rows show each action's conditional EV and the mixed EV. A group line weights those by the current marginals
- **Hand categories** on a five-card board: made-hand category fractions for each player from strategy-weighted reaches (not draws or backdoors)
- Export writes the node on screen. A node export carries values only after they were calculated for that same node

The default spot is aces versus kings on `Ah Kd 7c 4s 2h`. That is the same tree as `configs/river_default.json`, with 200 iterations instead of 500. A three-, four-, or five-card board calls `StreetBatchSolver`. `river_solver` remains the CLI entry over `RiverBatchSolver`. Every board length sends `memory_mib` (default 1024) and `threads` (default 1). The memory field is the street solver's heap budget. Threads above 1 require the frozen pass; a non-frozen request with more than one thread is rejected before the solve starts. If the tree does not fit, the page keeps running and shows the budget error. The 200,000-terminal limit belongs to the `StreetGame` reference enumerator.
